Livraison — Atelier de la Séduction (boutique-management-system)

État de l'application

  • App : vente « Atelier de la Séduction » — tableau de bord, ventes & caisse, catalogue, stock, clientes & répertoire, dépenses, activités, gestion des comptes.
  • Rôles : Administratrice / Associée / Caissière (permissions par rôle, comptes suspendus bloqués).
  • Sécurité : connexion par e-mail + mot de passe (scrypt), verrouillage après 5 échecs / 10 min, session JWT.
  • Tailles : gestion S/M/L/XL sur les produits à tailles (édition produit avec photo, ajustement par taille, vente avec taille, reçus, remboursement).
  • Base : PostgreSQL (Neon), migrations Drizzle (12 migrations, journal cohérent, vérifié le 23/11/2026).
  • Branches : le service dev tourne via pnpm dev sur le port 3000.

Nouveautés livrées le 23/11/2026 (Tâches 1 → 2 → 3)

  1. Facture multi-articles : une facture regroupe plusieurs lignes de vente ; panier caisse avec recherche/liste produit, quantité, prix unitaire prérempli (modifiable seulement par Admin/Associée), sous-totaux et total en direct, ajout/suppression de ligne, contrôle stock/taille/prix côté serveur, enregistrement atomique via public.create_invoice() (fonction PostgreSQL obligatoire avec neon-http, qui ne supporte pas db.transaction()). Les anciennes ventes mono-article sont reconstituées en factures d’une ligne par la migration 0010 (aucune perte). Le remboursement reste par ligne (comportement historique conservé).
  2. Exports PDF : jspdf + jspdf-autotable ; boutons CSV | PDF sur ventes, produits/stock, dépenses, clientes et rapport. Chaque PDF contient en-tête boutique + logo, titre, date, tableau paginé et totaux. Le CSV reste disponible tel quel.
  3. Logo configurable : réglages réservés à l’Administratrice, upload PNG/JPG ≤ 2 Mo redimensionné côté client (256 px, JPEG, sans déformation), stocké en base (store_settings, comme les photos produits — compatible Vercel), suppression possible, repli sur /logo.jpg si absent. Le logo apparaît sur le reçu écran/PDF/impression, les exports PDF et la page de connexion.
  • Dépendances ajoutées : jspdf@^4.2.1, jspdf-autotable@^5.0.9 (lockfile pnpm mis à jour).
  • Next.js 16 : la page /login lit le logo en base ; elle est exclue du prérendu avec await connection() de next/server (API recommandée, export const dynamic = 'force-dynamic' étant déprécié).
  • Vérifications techniques : pnpm exec tsc --noEmit ✓, pnpm build ✓ (routes / et /login dynamiques), pnpm db:migrate ✓, test doc.lastAutoTable.finalY sous autotable v5 ✓.

  • Vérification mobile (390×844) : aucune coupure, modales défilables.

Tâche 1 — Facture multi-articles

  • Caisse : ajouter 3 articles dont deux fois le même → le doublon est fusionné (quantité cumulée), total temps réel correct.
  • Modifier une quantité (1 → 3), supprimer une ligne, vérifier la mise à jour immédiate du sous-total et du total.
  • Prix prérempli depuis le catalogue ; tentative de modification en tant que Caissière → refus ; OK en Admin/Associée.
  • Quantité > stock → refus clair ; produit archivé → refus ; taille manquante sur un produit taillé → refus.
  • Facture vide → bouton « Encaisser » désactivé / erreur serveur si contourné.
  • Deux caisses en simultané sur le dernier article → une seule vente acceptée, l’autre en rupture (atomicité).
  • Reçu après vente : toutes les lignes apparaissent à l’écran, dans le PDF et dans l’impression ; total = somme des lignes.
  • Rembourser une ligne seulement d’une facture multi-lignes → stock réintégré pour cette ligne, le reste intact.
  • Historique : l’ancienne vente du 20/11 apparaît toujours (facture mono-ligne reconstituée).

Tâche 2 — Exports PDF

  • Sur Ventes, Produits/Stock, Dépenses, Clientes, Rapport : cliquer PDF → fichier téléchargé, en-tête avec logo, titre, date, tableau lisible.
  • Forcer un grand nombre de lignes (ou filtre large) → pagination correcte, totaux en pied, pas de chevauchement.
  • Cliquer CSV → export identique à l’ancien comportement.
  • PDF avec logo absent → en-tête propre (nom de la boutique seulement), pas d’image cassée.

Tâche 3 — Logo

  • Admin uniquement : Paramètres → uploader un PNG puis un JPG → aperçu carré, aucune déformation.
  • Fichier > 2 Mo ou mauvais type → refus avec message clair ; fichier valide → logo visible sur connexion, reçu, PDF.
  • Supprimer le logo → repli sur /logo.jpg partout ; recharger la page de connexion (doit refléter le changement).
  • Se connecter en Caissière/Associée → section Paramètres absente et action serveur refusée si appelée directement.

Règles d'exploitation

  • Ne jamais relancer pnpm db:seed sans sauvegarde — le seed standard efface TOUT (produits, ventes, clientes, dépenses et comptes) puis réimporte l'inventaire de démo.
  • pnpm db:seed -- --empty --yes : remet proprement la base vierge (0 produit, 0 vente, 0 dépense) tout en conservant les 3 comptes — à utiliser pour repartir d'un état neuf.
  • .env.local (contient DATABASE_URL, AUTH_SECRET) reste hors du dépôt git ; à sauvegarder hors-ligne.
  • pnpm db:migrate est sûr : no-op sur une base à jour, applique tout sur une base neuve.
  • Chaque ouverture de session d'édition : pnpm install (une seule fois), pnpm dev → http://localhost:3000.
  • Après une migration, refaire un export logique Neon dans _archive\boutique-management-system\ (l’export du 23/11 11:54 est antérieur aux migrations 0010/0011).

Incident de déploiement du 23/11/2026 — cause et résolution

  • Symptôme : tous les déploiements échouaient avant le build avec BUILD_ERROR: Resource provisioning failed (CLI, Git, preview, et même redéploiement d’une ancienne version READY).
  • Cause : le projet Vercel avait un store Supabase (supabase-cerulean-castle, projet sdvyaitemyqaajirghps) lié en preview + production, déclaré deployments.required: true et suspendu (plan gratuit inactif). Vercel tentait de le provisionner à chaque déploiement, indépendamment de DATABASE_URL qui pointe sur Neon.
  • Résolution (action humaine obligatoire) : déconnexion du store via vercel storage disconnect supabase-cerulean-castle --project gestionas (confirmation interactive). Seules les 16 variables POSTGRES_, SUPABASE_, NEXT_PUBLIC_SUPABASE_* (inutilisées) ont été retirées ; DATABASE_URL et AUTH_SECRET conservées.
  • Vérification : vercel storage status --project gestionas → « No storage resources are connected ». Déploiement suivant → READY.
  • À surveiller : si un nouveau store Supabase est lié au projet et suspendu, le problème reviendra. Garder le projet sans intégration Supabase (l’appli n’en a pas besoin).

Manuel d’utilisation — Atelier de la Séduction

Version : 23/11/2026 · Application : Gestion boutique Atelier de la Séduction. Ce guide est destiné à l’équipe de la boutique (Administratrice, Associée, Caissière).

1. Se connecter

  1. Ouvrir https://gestionas.vercel.app (ou http://localhost:3000 en local).
  2. Saisir l’e-mail et le mot de passe transmis en main propre.
  3. Cliquer sur Se connecter.
  • Après 5 erreurs de mot de passe, le compte est verrouillé pendant 10 minutes.
  • Un compte suspendu ne peut pas se connecter.
  • Le logo affiché sur cette page est celui configuré dans Paramètres (ou le logo par défaut).

Changer son mot de passe

Menu Comptes → Changer mon mot de passe (disponible selon votre rôle). Choisissez un mot de passe conforme aux règles affichées et ne le partagez pas.

3. Vendre avec une facture multi-articles (caisse)

C’est le parcours principal.

  1. Ouvrir Ventes & caisse.
  2. Dans la zone de recherche, taper le nom ou la référence d’un produit, puis cliquer sur le produit voulu.
  3. Pour un produit avec tailles (S/M/L/XL) : choisir la taille dans la liste.
  4. Ajuster la quantité. Le prix unitaire est rempli automatiquement depuis le catalogue.
  • Si vous êtes Administratrice ou Associée, vous pouvez modifier ce prix (ex. prix spécial).
  • Si vous êtes Caissière, le prix reste celui du catalogue.
  1. Cliquer sur Ajouter au panier. Répéter pour chaque article.
  • Si vous ajoutez deux fois le même article et la même taille, les quantités sont fusionnées sur une seule ligne.
  1. Vérifier le sous-total de chaque ligne et le total en bas du panier.
  • Pour changer une quantité : utiliser les boutons + / − ou le champ quantité.
  • Pour retirer un article : cliquer sur l’icône corbeille.
  1. Choisir la cliente (facultatif : recherche dans le répertoire, ou nom libre).
  2. Choisir le moyen de paiement : Espèces, Carte bancaire ou Mobile Money.
  3. Cliquer sur Encaisser.

Contrôles automatiques

La vente est refusée si : le panier est vide, la quantité est invalide, le stock est insuffisant, le produit est archivé, la taille est manquante ou inconnue, ou le prix est hors limites. Un message explique le problème : corrigez puis réessayez.

Après l’encaissement

Le reçu s’affiche avec toutes les lignes :

  • PDF : télécharge le reçu en PDF.
  • Imprimer : ouvre l’impression du reçu.
  • Le stock est décrémenté automatiquement (et par taille pour les articles taillés).

4. Rembourser un article

  1. Ouvrir Ventes & caisse → historique des ventes.
  2. Repérer la ligne à rembourser (dans une facture, chaque article est une ligne distincte).
  3. Cliquer sur Rembourser, choisir un motif, confirmer.
  4. Le stock de cet article est réintégré (et sa taille le cas échéant). Les autres lignes de la facture restent inchangées.

Une ligne ne peut être remboursée qu’une seule fois.

5. Gérer le catalogue

Réservé à l’Administratrice et à l’Associée.

  • Ajouter un produit : bouton en haut de Catalogue → renseigner nom, référence (SKU), catégorie, prix de vente, prix d’achat, stock, seuil d’alerte, photo.
  • Tailles : sur un produit de lingerie, activer les tailles S/M/L/XL et indiquer le stock de chaque taille.
  • Modifier / archiver : menu … sur la fiche produit. Un produit archivé n’est plus vendable mais reste dans l’historique.
  • Importer : bouton Importer → fichier CSV au format attendu (voir l’exemple exporté).
  • Exporter : boutons CSV et PDF.

6. Gérer le stock

Réservé à l’Administratrice et à l’Associée.

  • La page Stock affiche le stock disponible, le seuil minimum et les alertes « Stock à surveiller ».
  • Ajuster le stock : indiquer le nombre d’unités à ajouter ou retirer, et un motif.
  • Chaque ajustement est enregistré dans le journal d’activité.

7. Clientes, dépenses, rapports

  • Clientes & répertoire : ajouter une cliente (nom, téléphone, notes), la retrouver lors d’une vente, anonymiser ses données si besoin.
  • Dépenses : saisir libellé, catégorie, montant et date.
  • Rapports : consulter les indicateurs et exporter en CSV ou PDF.
  • Les exports sont disponibles aussi depuis Ventes, Catalogue/Stock, Dépenses et Clientes. Chaque bouton télécharge un fichier daté.

3. Flux métier principaux

3.1 Vente multi-articles (Tâche 1)

  1. Client (app/atelier-app.tsx) : l’utilisateur recherche un produit, l’ajoute au panier avec quantité et taille. Le prix est prérempli depuis le catalogue. Le total est calculé en direct.
  2. Action (registerSale, app/actions.ts) :
  • requireCapability('sales') ; moyen de paiement dans la liste autorisée.
  • 1 à 100 lignes ; quantité 1–999 ; prix 0–1 000 000.
  • Fusion des doublons même produit + même taille (côté client puis côté serveur).
  • Vérification produit actif, taille valide, stock disponible.
  • Le prix n’est modifiable que si can(role,'catalog') || can(role,'stock') (Admin/Associée) ; sinon le prix catalogue est forcé.
  • Résolution de la cliente (nom ou id).
  1. Écriture atomique : db.execute(sql\SELECT public.create_invoice(...)\). La fonction PostgreSQL insère la facture, les lignes, décrémente le stock (global ou par taille), écrit les mouvements, puis renvoie { invoiceId, total, itemCount, lines }.

neon-http ne supporte pas db.transaction() : la transaction est donc portée par la fonction SQL, en un seul appel.

  1. Sortie : toReceipt() construit un ReceiptData avec lines, invoiceId, invoiceTotal et les champs plats historiques (compatibilité anciens écrans). Activité journalisée, revalidatePath('/').
  2. Remboursement (refundSale) : agit sur une ligne (saleId), réintègre le stock (et la taille), écrit un mouvement, refuse un doublon. Le comportement historique est conservé.

3.2 Exports CSV / PDF (Tâche 2)

  • exportCSV(kind, filters) et exportReport() (app/actions.ts) retournent { ok, csv, pdf, filename }.
  • Le CSV reste construit par buildCSV() (BOM UTF-8 \uFEFF ajouté côté client).
  • Le PDF est une structure ExportTable (titre, sous-titre, blocs avec colonnes/lignes/totaux) transmise à buildExportPdf() (lib/pdf.ts).
  • buildExportPdf() : charge jsPDF/autotable en dynamique, A4 portrait (paysage si > 7 colonnes), en-tête boutique + logo (redimensionné proportionnellement dans 22×16 mm, repli silencieux si corrompu), date fr-FR, tableau grid, en-tête répété à chaque page, pied « Généré le … · Page x/{total} », totaux en fin de bloc.
  • saveBlob() (lib/pdf.ts) déclenche le téléchargement côté navigateur.

3.3 Logo configurable (Tâche 3)

  1. Client : resizeLogo() (app/atelier-app.tsx) lit le fichier, refuse > 2 Mo et tout type hors PNG/JPG, dessine sur un canvas 256×256 avec object-fit: contain (aucune déformation), exporte en JPEG q0,82 → data URL.
  2. Action uploadStoreLogo(dataUrl) : requireAdmin(), validation imageValue(), insert(...).onConflictDoUpdate() sur store_settings.id = 1, activité, revalidatePath('/') et revalidatePath('/login').
  3. Action removeStoreLogo() : remet logo = null ; l’interface affiche alors le logo livré /logo.jpg.
  4. Affichage : AppLogo / ReceiptMark (components/AppLogo.tsx) reçoivent src optionnel ; getStoreLogo() (lib/data.ts) alimente la page de connexion (via await connection() pour exclure le prérendu) et le tableau de bord.
  5. Le logo est aussi injecté dans les PDF d’export et le reçu PDF.

3.4 Authentification & sécurité

  • Session JWT Auth.js ; mot de passe haché avec scrypt ; verrouillage après 5 échecs / 10 minutes.
  • Chaque action sensible appelle auth() puis interroge la table users pour vérifier rôle ET statut (un compte suspendu est refusé même avec un JWT valide).
  • Les entrées sont validées côté serveur (quantités, prix, types MIME, tailles de fichier, motifs de remboursement).
  • .env.local (DATABASE_URL, AUTH_SECRET) reste hors git.
